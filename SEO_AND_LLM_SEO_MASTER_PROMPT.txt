SECTION 2: TRADITIONAL TECHNICAL & ON-PAGE SEO MANDATES
================================================================================
Perform a complete technical audit against these mandatory criteria:

2.1 Semantic HTML5 Architecture
- Enforce strict single <h1> per page that mirrors the primary search query target.
- Maintain unbroken hierarchical heading levels (H1 -> H2 -> H3; never jump H2 to H4).
- Use landmark elements: <header>, <nav aria-label="...">, <main id="main-content">,
  <article>, <section>, <aside>, and <footer>.
- Ensure all interactive links use descriptive anchor text (strictly ban "click here",
  "read more", "link", or naked URLs).
- Ensure all images have descriptive, contextual alt attributes (8-16 words, describing
  both the visual subject and its contextual relevance).

2.2 Metadata & Document Head Optimization
- <title>: Formatted as "[Primary Target Keyword] - [Secondary Context] | [Site Name]".
  Hard character budget: 50-60 characters (display width < 580px).
- <meta name="description">: Active voice, contains primary + LSI keywords, ends with a
  subtle call to action or key statistic. Budget: 135-155 characters.
- <link rel="canonical" href="[FULL_QUALIFIED_ABSOLUTE_URL]">: Enforce canonicals on every
  routable page to prevent query parameter and protocol duplication.
- OpenGraph & Twitter Cards:
  * og:title, og:description, og:url, og:type, og:site_name, og:locale
  * og:image: 1200x630px, < 300KB, with dedicated og:image:alt and og:image:type
  * twitter:card: summary_large_image, twitter:creator, twitter:site
- Favicons & PWA Manifest: Ensure SVG/ICO favicons, apple-touch-icon, and manifest.json.

2.3 Crawlability, Sitemaps & robots.txt
- Clean sitemap.xml listing all canonical HTML URLs with accurate <lastmod> timestamps.
- Zero orphaned pages: every indexable page must receive at least 2 internal links.
- No accidental noindex/nofollow on production pages.
- Set `<meta name="googlebot" content="max-video-preview:-1, max-image-preview:large, max-snippet:-1">`
  to maximize eligibility for rich cards, image packs, and Google Discover.

2.4 Performance & Core Web Vitals
- Largest Contentful Paint (LCP) < 2.5s: Preload hero fonts/images; inline critical CSS.
- Cumulative Layout Shift (CLS) < 0.1: Explicit width/height on all images, SVGs, and iframes.
- Interaction to Next Paint (INP) < 200ms: Eliminate heavy main-thread blocking scripts.

SECTION 3: LLM SEO / GENERATIVE ENGINE OPTIMIZATION (GEO) ARCHITECTURE
================================================================================
Generative Engine Optimization (GEO) targets how Large Language Models and AI search
agents (Perplexity, SearchGPT, Gemini, Claude) discover, read, index, and synthesize
content into answers and citations.

3.1 The /llms.txt and /llms-full.txt Standard
- Implement the official standard proposed by Jeremy Howard (Answer.ai):
  * `/llms.txt`: A concise, human-and-LLM-readable Markdown file serving as an index of
    the site, curated for LLM context windows (summaries, key pages, APIs, docs).
  * `/llms-full.txt`: A consolidated single-file markdown reference containing the
    entire essential knowledge base of the website, formatted cleanly without HTML tags,
    enabling instant full-context ingestion by AI chat models.
- Expose links to both in `<head>`:
  `<link rel="alternate" type="text/markdown" title="LLM Context" href="/llms.txt">`

3.2 AI Web-Crawler Matrix & robots.txt Strategy
AI search engines operate dedicated crawlers distinct from traditional search bots.
Your robots.txt policy must distinguish between search/answer retrieval crawlers and
indiscriminate offline model trainers:
- Crawlers to ALLOW for AI search citation:
  * GPTBot & OAI-SearchBot (OpenAI / SearchGPT)
  * PerplexityBot (Perplexity AI)
  * ClaudeBot & Claude-Web (Anthropic / Claude Search)
  * Google-Extended & GoogleOther (Google Gemini / Vertex)
  * Applebot-Extended (Apple Intelligence)
  * Cohere-training-data-crawler / Cohere-ai
  * Bingbot (Microsoft Copilot)

3.3 Entity Graph Disambiguation (Schema.org JSON-LD @graph)
AI models do not index text as isolated strings; they map entities in a Knowledge Graph.
You must construct a unified `@graph` JSON-LD array linking:
- Person / Organization (@id based, globally referenceable)
- WebSite & WebPage (@id tied to the URL)
- ProfilePage (for author/about pages)
- TechArticle / BlogPosting (with explicit `about`, `mentions`, `citation`, `author`, `keywords`)
- SoftwareSourceCode / SoftwareApplication (for code projects, with `codeRepository`,
  `programmingLanguage`, and `runtimePlatform`)
- `sameAs` array connecting to verified external authority nodes:
  Wikidata entity URLs, Wikipedia, LinkedIn, GitHub, ORCID, Google Knowledge Graph IDs.

3.4 Semantic Chunking & Retrieval-Augmented Generation (RAG) Optimization
When an AI search engine fetches your page, its retrieval pipeline splits the text into
vector chunks (typically 250-600 tokens). To ensure your content is selected and cited:
- The "Inverted Pyramid" Structure: Lead every section with the core conclusion or
  direct definition within the first 40-60 words.
- Context-Independent Headings: Headings must be self-explanatory. Instead of "Overview",
  use "Overview of Neural Network Forward Propagation in C".
- Low Pronoun Ambiguity: Avoid opening paragraphs with "It does this..." or "They found...".
  Explicitly restate the entity or topic name ("The C neural network library implements...").
- High Information Density (Information Gain):
  * Include concrete quantitative data, benchmarks, timings, and code examples.
  * Use structured comparison tables (LLM embedding models prioritize markdown tables).
  * Include structured lists (ordered steps, bulleted trade-offs).
- Quotable Excerpts: Provide succinct, punchy authoritative statements formatted for
  direct extraction into AI summary cards.

3.5 Answer Engine Optimization (AEO) & Natural Language Queries
- Add dedicated Question-and-Answer or FAQ modules answering conversational queries:
  "How does [Topic] work?", "Why choose [Tech X] over [Tech Y]?", "What are the common vulnerabilities in [Topic]?".
- Mirror actual user search prompts found in "People Also Ask" and Perplexity user queries.

SECTION 5: SYSTEMATIC IMPLEMENTATION WORKFLOW
================================================================================
When this prompt is activated, execute the optimization in five sequential phases:

PHASE 1: Codebase & Semantic Discovery
1. Parse the site structure, routing, CMS files, templates, and build pipeline.
2. Extract all existing metadata, canonical rules, open-graph generators, and sitemaps.
3. Identify missing SEO tags, broken hierarchies, or duplicate content vectors.

PHASE 2: Infrastructure & LLM Discovery Deployment
1. Generate or update `/robots.txt` ensuring all major AI search crawlers are allowed.
2. Create `/llms.txt` at the root domain following the Answer.ai specification.
3. Build a generation script or static compilation step that gathers all markdown
   content into `/llms-full.txt` during the build step.
4. Add `<link rel="alternate" type="text/markdown" href="/llms.txt">` to HTML headers.

PHASE 3: Knowledge Graph & JSON-LD Expansion
1. Inject or enhance Schema.org `@graph` structures across all site templates.
2. Link the primary Person/Organization node to verified `sameAs` authorities (Wikidata, GitHub, etc.).
3. Add `BreadcrumbList`, `TechArticle`, `ProfilePage`, and `SoftwareSourceCode` schemas.
4. Validate that `@id` cross-references resolve cleanly across the entire site graph.

PHASE 4: Content Restructuring for Generative Engine Ingestion
1. Add an "Executive Summary / Key Takeaways" direct-answer callout at the top of every post.
2. Ensure every post contains at least one structured markdown table or benchmark breakdown.
3. Replace generic headings ("Overview", "Details", "Conclusion") with context-dense,
   keyword-specific headings.
4. Add an authoritative FAQ section answering real conversational queries.

PHASE 5: Build Automation & Output Verification
1. Run the static site build command or compilation script.
2. Verify that all emitted HTML files contain matching title tags, meta descriptions,
   canonical URLs, and valid JSON-LD scripts.
3. Check the output directory (`/dist/` or `public/`) for the presence of `/robots.txt`,
   `/sitemap.xml`, `/llms.txt`, and `/llms-full.txt`.
